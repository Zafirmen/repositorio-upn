Centro de Documentación

A continuación encontrarás todas las instrucciones necesarias para colaborar en el repositorio departamental directamente desde esta página.

Guía de Contribución

Normas generales para garantizar la consistencia en todos los proyectos subidos:

  • Convenciones de Ramas: Todas las ramas nuevas deben empezar con feature/ seguido del nombre del proyecto. Ejemplo: feature/brazo-robotico.
  • Estructura Obligatoria: Cada proyecto debe vivir dentro de una carpeta que incluya un archivo metadata.json, una imagen representativa y el archivo base index.html (o equivalente).
  • Commits: Utilizar el estándar de Conventional Commits (ej. feat: añade prototipo IoT, fix: corrige dimensiones CSS).

Guía para Docentes

Instrucciones específicas para el flujo de validación:

  • Revisión de Estudiantes: Los proyectos de estudiantes deben ser sometidos a través de Pull Requests.
  • Aprobación: El docente encargado del seminario o materia debe realizar un Approve oficial en GitHub antes de hacer merge a main.
  • Publicación: Una vez aprobado, el sistema de integración desplegará automáticamente el proyecto en la galería y actualizará el archivo `proyectos.html`.

Usuarios Autorizados

Cómo colaborar si no perteneces a la organización de GitHub del Departamento:

  • Realiza un Fork del repositorio principal hacia tu cuenta personal.
  • Clona tu fork localmente en tu computadora.
  • Agrega tu proyecto en la carpeta correspondiente.
  • Crea un Pull Request desde tu Fork hacia el repositorio principal de la UPN.

Política de Seguridad

Lineamientos para mantener la integridad del repositorio:

  • Protecciones de Rama: La rama main está protegida y no permite pushes directos, excepto por los administradores de sistemas designados.
  • Autenticación 2FA: Todos los colaboradores con acceso de escritura deben tener activada la autenticación de dos pasos (2FA) en GitHub.
